# 「留不留」产品计划书

> 一句话：**像刷卡片一样清理相册 —— 左滑删除，右滑保留。**

版本：v0.1（初始 idea 完善版）

---

## 1. 产品定位

「留不留」是一款**相册清理工具**，把"翻相册挑照片删"这件枯燥、有心理压力的事，改造成类似 Tinder 的滑卡体验：

- 所有待清理的照片以**卡片堆**的形式堆在屏幕中央，视觉上有"一摞照片等你处理"的实感
- 永远只看最顶上**一张**照片，一次只做一个决定：**左滑删除，右滑保留**
- 每滑一张，卡片飞走、下一张升起，伴随轻震动和音效，形成"停不下来"的心流节奏

**核心差异点**：系统相册的删除是"多选 → 勾选 → 删除"，决策成本集中在最后一步，压力大、易误删、无乐趣。「留不留」把决策拆成一张张即时反馈的小决定，把清理变成游戏。

## 2. 痛点与目标用户

**痛点**

1. 手机照片动辄几千上万张，存储告急，但"没时间/懒得整理"
2. 整理时要在大图和小图间反复横跳，效率低
3. 删除有心理负担——"万一以后要用呢"，于是永远不删
4. 相似连拍、截屏、模糊废片大量堆积

**目标用户**

- 主力：18–35 岁，照片 5000+、存储常年 90%+ 的用户（宝妈、旅行爱好者、追星族、内容创作者）
- 次力：换机前想精简相册的人；喜欢"断舍离"类工具的效率用户

## 3. 核心体验设计（最重要，逐条打磨）

### 3.1 卡片堆视觉

- 屏幕中央显示一摞照片卡，最顶上 1 张清晰，底下 2–3 张露出边缘、带 ±5° 随机旋转和缩放递减，营造"堆满了你所有照片"的感觉
- 卡片带白色相纸边框，底部一行小字：`IMG_2048.jpg · 2.4 MB · 2024/05/12`
- 顶部进度条：`2024 年 5 月 · 已看 128 / 356 张`，给用户明确的目标感

### 3.2 滑动手势

- 拖动时卡片跟随手指，随横向位移旋转（最大 ~15°）
- 位移超过阈值（约屏宽 25%）后松手，卡片带抛物线飞出屏幕；未过阈值则回弹
- 拖动过程中卡片上实时浮现半透明印章：**左滑红色「删除」、右滑绿色「保留」**，透明度随位移加深，反馈即时
- 飞出瞬间触发轻震动（haptic）+ 短音效（可关闭）

### 3.3 安全与反悔机制（删除类产品的生命线）

- **撤销**：底部中央常驻"撤销"按钮，可连续撤销多步；飞出的卡片飞回来
- **回收站缓冲**：左滑的照片**不是立即删除**，而是进入 App 内回收站；一轮清理结束后进入"确认页"统一执行系统级删除（iOS 删除相册照片必须弹系统确认框，正好作为最终防线）
- 回收站保留 7 天，期间可随时恢复

### 3.4 节奏感设计

- 每清理 20 张弹一个小激励："已释放 58 MB，继续！"
- 清理完一个相簿进入**结算页**：本次删除/保留张数、释放空间、本月对比，制造成就感

## 4. 功能清单

### 4.1 MVP（V1.0，只做这些）

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 相册权限引导 | 首次启动解释用途，申请权限；被拒绝时给出引导页 |
| P0 | 卡片堆滑卡清理 | 上述全部手势与动画 |
| P0 | 撤销（多步） | |
| P0 | 回收站 + 结束确认删除 | 调系统删除接口，二次确认 |
| P0 | 按范围清理 | 全部照片（从最近/最旧开始）、按月份 |
| P0 | 结算页 | 张数 + 释放空间统计 |
| P1 | 跳过/待定 | 上滑 = "暂不确定"，放回堆底（可选，手势不冲突才加） |
| P1 | 设置 | 音效/震动开关、回收站保留天数 |

### 4.2 V2.0（验证留存后做）

- **智能分组**（端上本地识别，不上传）：
  - 相似照片/连拍分组：一组成一张卡，默认保留最佳一张
  - 截屏、模糊照片、纯黑/纯白废片专项清理
- **大视频清理**：按体积排序，同样滑卡
- 清理日历/连续打卡、累计释放空间总榜
- iOS 桌面小组件（"本月已清理 xxx MB"）
- 多语言出海（这个品类在海外已被验证：Slidebox、Swipewipe 靠订阅制活得很好）

## 5. 关键流程

```
首次启动 → 权限引导 → 选择清理范围（月份/全部/截屏…）
        → 滑卡清理（撤销随时可用）
        → 本轮结束 → 结算页（统计 + 回收站入口）
        → 确认删除（系统弹窗）→ 完成页/继续下一组
```

## 6. 技术方案

- **推荐双端原生**（相册性能敏感）：
  - iOS：SwiftUI + PhotoKit（`PHAsset` 删除必须经系统确认弹窗，天然合规）
  - Android：Kotlin + Jetpack Compose + MediaStore（Android 11+ 有 `createTrashRequest` / 删除需系统授权弹窗）
- 想快速验证可先用 **Flutter**（photo_manager 插件）出双端 Demo，验证留存后再原生重写
- **纯本地运行**：照片不出设备，无服务器，隐私本身就是卖点（隐私政策极简单）
- 智能识别（V2）用端上模型：iOS Vision 框架 / Android ML Kit，指纹哈希做相似图聚类

## 7. 商业模式

- 免费：基础滑卡清理、按月份清理
- **Pro（买断 ¥18–30 或订阅 ¥8/月）**：相似照片分组、视频清理、无限撤销、自定义回收站天数、主题
- 参考：海外同类产品订阅制 ARPU 表现稳定，工具类付费点清晰

## 8. 数据指标（上架后重点看）

- 次日/7 日留存（工具类基准：次留 30%+ 算健康）
- 人均单次滑动张数（目标 > 50，验证"停不下来"）
- 一轮清理完成率、删除/保留比
- 撤销使用率（过高说明误操作多或决策犹豫，要优化交互）

## 9. 里程碑

| 阶段 | 内容 | 周期 |
|---|---|---|
| M1 | 高保真原型（Figma）+ 内部体验手势手感 | 1–2 周 |
| M2 | MVP 开发（单端先行，建议 iOS） | 4–6 周 |
| M3 | TestFlight 灰度 100 人，看留存和人均滑动数 | 2 周 |
| M4 | 上架 App Store + 安卓补齐 | 2–4 周 |
| M5 | V2 智能分组 + 付费点 | 视数据启动 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 误删投诉 | 回收站缓冲 + 系统二次确认 + 撤销；永远不即时删除 |
| 平台审核（相册权限敏感） | 权限用途写清楚、纯本地、无上传；隐私政策极简 |
| 同质化（Slidebox 等已存在） | 打中文体验 + 本地化（微信截图专项、打卡分享），出海则打价格差 |
| 用户清理完就流失 | 每月新照片提醒、智能专项（截屏/相似）制造持续场景 |
